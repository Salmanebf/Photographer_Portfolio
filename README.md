# Documentary Filmmaker Portfolio

A cinematic, single-page portfolio for a documentary filmmaker (placeholder persona: **Alex Rivera**),
plus one detail page per film. Built with **Next.js 16 (App Router) · React 19 · Tailwind CSS 4 ·
Framer Motion**, with an optional **Sanity CMS** and a **Prisma + SQLite** contact-form backend.

> The repository is named `Photographer_Portfolio`, but the content is documentary-film focused.
> `package.json` is still named `nextjs_tailwind_shadcn_ts` (scaffold leftover).

For non-developer content editing, read [`CONTENT.md`](./CONTENT.md).
Chronological history lives in [`worklog.md`](./worklog.md).

---

## Quick start

```bash
npm ci                      # (or `bun install` — both lockfiles exist, see Known issues)
cp .env.example .env.local  # optional: only DATABASE_URL is really needed
npx prisma generate
npx prisma db push          # creates prisma/db/custom.db
npm run dev                 # http://localhost:3000
```

| Command             | What it does                                                                 |
| ------------------- | ---------------------------------------------------------------------------- |
| `npm run dev`       | Next dev server on :3000 (output also tee'd to `dev.log`)                    |
| `npm run build`     | `next build` (standalone output) + copies `.next/static` and `public` into it |
| `npm run start`     | Runs `.next/standalone/server.js` **with bun**                                |
| `npm run lint`      | ESLint (very permissive config — see Known issues)                           |
| `npm run typecheck` | `tsc --noEmit`                                                               |
| `npm run db:*`      | Prisma `push` / `generate` / `migrate` / `reset`                             |

There is **no test suite**.

## Architecture

```
Browser ──► Next.js (App Router, port 3000)
              │
              ├─ /                 server component: fetches 4 datasets, renders all sections
              ├─ /work/[slug]      SSG + ISR (revalidate 60s) per-film page
              ├─ /studio/[[...tool]]  embedded Sanity Studio (client component)
              ├─ /api/contact      POST: validate → rate-limit → SQLite (Prisma) → optional Resend email
              │                    GET : admin list, gated by CONTACT_ADMIN_TOKEN
              ├─ /api              leftover "Hello, world!" route
              ├─ /sitemap.xml, /robots.txt   generated by src/app/sitemap.ts, robots.ts
              │
              ├─ Data layer  src/lib/queries.ts ──► Sanity (if configured) ──fallback──► site.config.ts + data.ts
              └─ Prisma → prisma/db/custom.db (SQLite)   model ContactMessage
```

### The key idea: CMS with graceful fallback

`src/lib/queries.ts` is the single data-access layer. Every getter (`getSiteSettings`, `getProjects`,
`getProjectBySlug`, `getServices`, `getTestimonials`) does:

1. If `NEXT_PUBLIC_SANITY_PROJECT_ID` is unset → return static fallback (`site.config.ts` / `data.ts`).
2. Otherwise run a GROQ query; on error or empty result → fall back to static data.
3. For settings, Sanity values are **merged field-by-field over** the static config (empty CMS field = keep default).

So the site works with zero external services, and editing is "code-only" (Path A) or "Studio" (Path B).

### Rendering model

- `/` and `/work/[slug]` are server components that pass plain props to client section components.
- Both use ISR (`revalidate = 60`); Sanity client also uses the CDN in production.
- Scroll/entrance animation = `useScrollReveal` (IntersectionObserver adds a `.revealed` class) +
  CSS utility classes (`slide-left`, `scale-fade`, `blur-in`, …) in `globals.css`; heavier motion
  (hero parallax, letterbox bars, preview panel) uses Framer Motion.
- Theme is dark-only (`<html class="dark">`); the accent colour is the `--gold` CSS variable,
  overridden at runtime from `brand.color`.

### Data model

`DocumentaryProject` (`src/lib/data.ts`): `id, slug, title, subtitle, category, image, year, duration,
location, shortDescription, fullDescription, awards[], credits[{role,name}], gallery[], tags[], video?, featured?`.
Sanity `project` mirrors it, plus `order`. `ContactMessage` (Prisma): `id, name, email, subject, message, read, createdAt, updatedAt`.

### Environment variables

| Variable                                          | Purpose                                                          |
| ------------------------------------------------- | ---------------------------------------------------------------- |
| `DATABASE_URL`                                    | SQLite path. **Use an absolute path in production** (see issues) |
| `NEXT_PUBLIC_SANITY_PROJECT_ID`, `..._DATASET`    | Enables Sanity; unset = static fallbacks                         |
| `NEXT_PUBLIC_SITE_URL`                            | Canonical/OG/sitemap base URL                                    |
| `RESEND_API_KEY`, `CONTACT_NOTIFICATION_EMAIL`    | Optional email on new contact message                            |
| `CONTACT_ADMIN_TOKEN`                             | Enables `GET /api/contact` (Bearer token); unset = 404           |
| `NEXT_PUBLIC_ENABLE_ANALYTICS`                    | Enables beacon to `/api/analytics` (**endpoint does not exist**) |

### Deployment

- `output: "standalone"`; run with `node`/`bun .next/standalone/server.js`. Remember to copy
  `.next/static` and `public` (the `build` script does this).
- `.zscripts/*` are scripts for the original hosting platform (Chinese comments): `build.sh` hard-codes
  `/home/z/my-project` and requires a root-level `./db/custom.db`; `start.sh` expects `/app/db/custom.db`
  and a `caddy` binary. They will not work unmodified elsewhere. `mini-services/` is empty.
- Vercel/Node hosts: ignore `.zscripts`, set env vars, and give SQLite a persistent absolute path
  (or migrate the contact form to a hosted DB — SQLite on serverless is not persistent).

## Known issues (audit of 2026-10-07)

Verified: `npm ci`, `tsc --noEmit`, `eslint .` and `next build` all pass. Behaviour below was checked
against a running production build and dev server unless marked *(code review)*.

### Bugs (functional)
1. **Contact form returns 500 in the standalone/production build with the default `DATABASE_URL=file:./db/custom.db`.**
   Prisma resolves the relative path from its generated client directory, not `prisma/`; dev works, prod
   fails with "Unable to open the database file". Works with an absolute path.
2. **Honeypot is broken.** Zod's `website: z.string().max(0)` rejects bot input with HTTP 400, so the
   "silently succeed" branch in `route.ts` is dead code and bots learn the trap.
3. **Rate limit is bypassable.** The key is the first `X-Forwarded-For` value, which clients can spoof
   (8 requests with rotating fake IPs all succeeded; the same IP is blocked after 4–5). Also in-memory,
   so per-instance only.
4. **Sanity `video` is dropped.** `normalizeSanityProject` never maps `video` (or `featured`), so a trailer set
   in the Studio never appears; only the static fallback data can have a video.
5. **Nav/footer links do nothing on `/work/[slug]`.** `Navigation` and `Footer` use
   `document.getElementById(...)`, but those section IDs don't exist on film pages; they should link to `/#section`.
6. **Newsletter "Join" form is a stub.** `onSubmit` only calls `preventDefault()` — no request, no feedback,
   emails are discarded.
7. **Analytics sends to a non-existent endpoint.** With `NEXT_PUBLIC_ENABLE_ANALYTICS=true`, `sendBeacon('/api/analytics')`
   returns 404. Also only fires on the first load and `popstate` (not client-side navigation).
8. **`aboutQuote` split bug.** The CMS quote is split on the first comma; if it has no comma, the new text is combined with
   the *default* accent (" you uncover it.").
9. **Meta description / keywords / OG title are not CMS-driven.** Sanity "Meta Description" (`description`) is never read;
   `siteConfig.seo.description` is always used. `siteConfig.seo.title` is unused.
10. **Studio / CLI branding hard-coded** ("Alex Rivera — Studio", `studioHost: 'alexrivera-studio'`).

### Security / hardening
- `npm audit --omit=dev`: 48 advisories (2 critical, 28 high), notably `next` (16.2.4 → upgrade to a patched release),
  `ws`, `vite`/`valibot` (via Sanity), `prisma`, `resend`. Run `npm audit fix`, then re-test.
- `Caddyfile`: any request with `?XTransformPort=<n>` is proxied to `localhost:<n>` — an open proxy to internal ports
  if exposed publicly. Remove or restrict it before production.
- `layout.tsx` injects `brand.color` into an inline `<style>` via `dangerouslySetInnerHTML` without sanitising. The Studio
  validates hex, but API writes could bypass it — validate `/^#[0-9a-f]{3,8}$/i` server-side. *(code review)*
- No security headers/CSP are configured. `GET /api/contact` compares the token with `!==` (not constant-time).
- `.env` is **committed** despite `.gitignore` (currently only `DATABASE_URL`, but remove it from git: `git rm --cached .env`).
- Email is sent from `onboarding@resend.dev` (Resend sandbox: only delivers to the account owner) and is
  fire-and-forget (`void sendEmail`), which can be cut off on serverless runtimes. *(code review)*
- `lib/db.ts` logs every SQL query (`log: ['query']`) in all environments.

### Quality / maintainability
- **ESLint is effectively disabled**: `no-unused-vars`, `exhaustive-deps`, `no-undef`, `no-explicit-any`, etc. are off, so
  "lint passes" proves little. With them on there are only 2 warnings (unused `useCallback`, `actionTypes`), so re-enabling is cheap.
  No tests, no CI.
- Two lockfiles (`bun.lock`, `package-lock.json`) can drift; scripts mix `npm`, `bun`, and `tee` (which hides the exit code).
- `skills/` (18 MB, incl. `.pyc` files and a `tectonic` binary) is committed although `.gitignore` lists it; it is unrelated to the
  site. Remove from git (`git rm -r --cached skills`).
- Dead code: `app/api/route.ts`, `useParallax`, `useLockBodyScroll`, `hooks/use-mobile.ts`, `VideoPlayer ambient` prop, and the
  velocity/direction logic in `AwardsMarquee` (computed but never used). `public/robots.txt` is shadowed by `app/robots.ts`.
- Duplicate Sanity fetches per request (`getSiteSettings` in layout, metadata and page) — wrap in `React.cache`.
- Accessibility/semantics: two `<h1>` in the hero; film page shows "1 Awards"/"0 Awards" and an empty Gallery heading;
  `credit.role` used as React key (duplicates collide); nav "active section" uses scroll handler rather than IntersectionObserver.
- `useCountUp` doesn't cancel its `requestAnimationFrame`. Sitemap `lastModified` is always "now".
- `next/image` is only allowed for `cdn.sanity.io` and `images.unsplash.com`; any other host in CMS data throws at render.
- Process steps in Services and the award names in `AwardsMarquee` are hard-coded (not editable via CMS).
